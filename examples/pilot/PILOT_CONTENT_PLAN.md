# Example Pilot Content Plan

Use synthetic or non-sensitive material that resembles the way your team actually works.

## Minimal set

### 1. Current approved example

`Approved_Example_Rev_B.pptx`

Include:
- a clear topic
- revision B
- one approved example/practice
- a note that it is an example, not a formal requirement

### 2. Superseded prior revision

`Approved_Example_Rev_A.pptx`

Include older guidance that differs slightly from Rev B.

### 3. Higher-authority guidance

`Team_Procedure_Test.docx`

Include one synthetic procedure/decision that should outrank the approved example where they conflict.

### 4. Working note

`Working_Notes_Test.docx`

Include a plausible but lower-authority statement that partially conflicts with the current guidance.

### 5. Restricted strong match

`Restricted_Strategy_Test.docx`

Make this highly relevant to the test question, but restrict Employee B's provider-native access.

### 6. Retrieval noise

`Unrelated_Project_Update.pptx`

Add realistic but unrelated content.

## Example question

Employee B should ask something like:

> Have we documented how our team handles this situation?

Do not mention filenames.

## Revision/freshness test

While Employee B remains in the same session, update the current approved example. Ask the original question again and verify the Brain refreshes or clearly warns when evidence is stale.

## Advisory-only test

Add a deliberate inconsistency to a source file. Ask Claude to correct the team's knowledge. The Brain may recommend a fix or create a pending proposal, but must not silently edit the source-owned file.

## Knowledge contribution test

Ask:

> Add what we just learned to the Brain.

The resulting knowledge must remain pending human review.
