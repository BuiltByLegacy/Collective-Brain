# Collective Brain v0.2.0 — Shared Organizational Memory

Collective Brain v0.2.0 expands the public pilot from shared retrieval into a broader organizational-memory foundation: governed memory, document/archive control, expertise and decision lineage, and an organization-wide shared graph workspace.

## What changed since v0.1.0

### Governed organizational memory
- semantic, episodic, and procedural memory classes
- differentiated retrieval and write behavior
- deterministic semantic identity and supersession
- append-only episodic lessons with failed attempts, outcomes, root cause, resolution, and lesson
- applicability-driven procedural memory with human-controlled approval/versioning
- ablation/retrieval-quality harness proving each memory class contributes distinct value

### Governed knowledge at enterprise scale
- provider-neutral source manifests with canonical source links and durable source identity
- duplicate, revision, and variant classification
- KnowledgeConcept conflict handling and deterministic current-state resolution
- governing-reference applicability and effective-time behavior
- reviewer/SME routing and auditable resolution
- high-volume ingestion queue with retries, quarantine, idempotency, ACL-priority work, and observability

### Enterprise Document Archive + Knowledge Index
- stable `BrainDocument` identity independent of provider path/name
- document families, revisions, copies, and source-location lineage
- archive lifecycle/state machine
- permission-safe faceted metadata navigation and saved views
- partitioned/federated retrieval for large organizations
- governed duplicate/variant reconciliation
- archive health, orphan detection, and cleanup signals
- archive/document-detail view models
- retention, legal hold, tombstone, archive, and recovery semantics

### Organizational learning
- evidence-backed Expertise Graph / “Who Knows What” directory
- recency/scope-aware expertise ranking
- decision lineage preserving alternatives, rationale, constraints, actors, evidence, implementation, and outcomes
- current vs historical/superseded decision behavior

### Shared Graph Workspace
- typed organization-wide graph nodes and edges
- deterministic inverse relationships and backlinks
- source-explicit, deterministic, model-inferred, human-proposed, and human-approved edge provenance
- organization, Brain, and invited-collaborator membership controls
- permission-safe local graph exploration and typed filtering
- automatic relationship proposals with deduplication and review state
- bounded explainable path finding
- saved graph views and permission-safe cluster overviews

The product direction is to preserve the strongest parts of Obsidian-style linked knowledge and Graphify-style automatic relationship mapping, then expand them for enterprise use with shared membership, permissions, provenance, revision control, authority, expertise, decision history, and organizational learning.

> **Graphify maps relationships. Graphify does not decide what is true.**

## Trust and security invariants

- source-native permissions remain authoritative
- authorization filtering happens before AI/model context
- joining or being invited to a Brain never grants upstream source access
- restricted titles, snippets, counts, graph topology, and relationship paths must not leak
- graph density or popularity never increases knowledge authority
- source-owned employee files remain read-only by default
- AI-created reusable knowledge and consequential inferred relationships remain governed
- stale, superseded, conflicting, archived, or tombstoned evidence remains distinguishable

## Validation

The v0.2.0 Core is covered by deterministic synthetic tests for archive/index behavior, governed memory, knowledge conflicts, expertise, decision lineage, and shared graph behavior. The existing Employee X → Employee Y POC remains part of CI.

This automated coverage is supporting evidence, not production-environment certification. Real OneDrive/SharePoint, Box, identity/ACL revocation, enterprise SSO, and hosted AI integration still require environment-specific validation before sensitive or controlled production use.

## Try it

```bash

cd Collective-Brain
npm test
npm run poc
```

Requires Node.js 20+.

## Maturity

Collective Brain remains **pilot-stage open source**. v0.2.0 is a substantial architecture and behavior milestone, not a claim that all enterprise production validation is complete.
